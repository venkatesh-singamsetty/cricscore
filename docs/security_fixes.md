# Security Fixes & Change Log (feat/python-ai-service)

Found during the AI-platform audit. All fixes are covered by automated tests (`npm --prefix apps/backend test`, `apps/ai-service` pytest).

| #   | Severity | Issue                                                                                                                                                                                                            | Fix                                                                                                                                                                                                                                                     |
| --- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Critical | `POST /chat` trusted `isAdmin` from the request body, so anyone could call destructive MCP tools (`delete_guest_data`, `delete_incomplete_matches`).                                                             | `chatHandler.js` ignores `isAdmin`; destructive tools are never registered in chat. The system prompt tells the assistant to refer deletions to Match Ops. Users can chat but cannot delete.                                                            |
| 2   | Critical | `POST /rules/upload`, `GET /rules`, `DELETE /rules` had no authentication (anyone could replace or delete rulebooks and spend embedding credits).                                                                | Terraform: routes now use the Cognito JWT authorizer. `chat-api/config/auth.js` `requireAdmin` re-checks the verified claims (`Admin` group exact match or `ADMIN_REPORT_EMAIL`) and returns 403 otherwise. `ADMIN_REPORT_EMAIL` added to chat-api env. |
| 3   | High     | `match-api` accepted an `x-scorer-email` header and granted the **Admin** group when no JWT claim existed (privilege escalation on unauthenticated routes). `score-update` also trusted the header for identity. | Header-derived identity/roles removed from both. Identity comes only from verified JWT claims.                                                                                                                                                          |
| 4   | Medium   | Admin group check used substring matching (`"NotAdmin"` matched).                                                                                                                                                | Exact group-name matching in `match-api` and `chat-api`.                                                                                                                                                                                                |
| 5   | Medium   | `execute_sql` relied only on `BEGIN READ ONLY` for LLM-generated SQL.                                                                                                                                            | Pre-validation: a single `SELECT`/`WITH` only; write/DDL keywords and `pg_sleep`, `pg_read_file`, `dblink`, etc. rejected before any DB call.                                                                                                           |
| 6   | Low      | Client chat history could include `system`/`tool` roles (prompt injection).                                                                                                                                      | History limited to `user`/`assistant`, last 10 turns.                                                                                                                                                                                                   |

## Other changes

- New `apps/ai-service` (Python 3.12): deterministic router, LangGraph supervisor with bounded specialists, parameterized read-only tools, optional LangSmith (off by default, payloads hidden). **Not yet wired into chat-api and not deployed.**
- `.gitignore`: `apps/ai-service/.venv/`, `.pytest_cache/`.
- `docs/api.md`, `docs/ai_architecture.md`, `docs/testing.md` updated. `docs/changelog.md` is generated by semantic-release from the conventional commits on merge.

## Behavior changes to know about

- Rulebook list/upload/delete now require an admin login; the current frontend only has stubs for these, so no UI regression is expected.
- Chat can no longer perform deletions for anyone, including admins.

## Remaining known gaps

- `/chat` and `/chat/summary` are unauthenticated (guest chat is intentional); add throttling/WAF-style limits if abuse appears. LLM calls cost money.
- `execute_sql` still uses the app DB role; use a dedicated read-only Postgres role (planned with the Python service).
- CORS is `*` on chat-api.
